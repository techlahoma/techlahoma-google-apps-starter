  accessibility expectations, and review evidence for __PROJECT_NAME__.
- `Why it matters:`
  - Screen work drifts when only the happy-path picture is specified.
  - Future reviewers need to know what question an artifact answers.
- `Go deeper:`
  - Start new work from `docs/templates/ux-frame.md`.
  - Review implemented screens with `docs/templates/screen-review.md`.

## Folder contract

- UX frames define goals, states, inputs, transitions, platform fit, and
  accessibility before tasking.
- Screen reviews record the tested revision, viewports, data states, findings,
  and verdict.
- Visual artifacts contain no real sensitive data and link back to their
  evidence record.

Create additional subfolders only when real artifacts need them.

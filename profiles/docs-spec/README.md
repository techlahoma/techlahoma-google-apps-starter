# Docs-spec Profile

- `Tease:` Specifications remain navigable, private when required, and honest
  about unknowns.
- `Lede:` This profile adds an anti-hallucination open-questions surface,
  docs-release proof, and a read-only public/anonymous route check without
  choosing a documentation framework.
- `Why it matters:`
  - A deployed documentation asset does not prove routing, authentication, or
    cache behavior.
  - Unresolved product questions should not be filled by plausible agent prose.
- `Go deeper:`
  - Choose the docs framework and authentication boundary separately.
  - Treat the authenticated route check as required evidence when docs are
    private.
